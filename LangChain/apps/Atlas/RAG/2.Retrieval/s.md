这是 **TF-IDF** 计算公式，信息检索的基石算法。逐行解释：

## 三个公式

### 1. TF（词频 Term Frequency）

$$\text{TF} = \frac{n_d^w}{n_d}$$

| 符号 | 含义 |
|------|------|
| $n_d^w$ | 词 $w$ 在文档 $d$ 中出现的次数 |
| $n_d$ | 文档 $d$ 的总词数 |

**直观**：这个词在文档里出现的频率有多高？

```
例: 文档 "CRISPE 框架 CRISPE 提示词"
     "CRISPE" 出现了 2 次，总词数 4
     TF("CRISPE") = 2/4 = 0.5
```

---

### 2. IDF（逆文档频率 Inverse Document Frequency）

$$\text{IDF} = \log\left(\frac{n_D}{n_D^w}\right)$$

| 符号 | 含义 |
|------|------|
| $n_D$ | 文档库中文档总数 |
| $n_D^w$ | 包含词 $w$ 的文档数量 |

**直观**：这个词在整个文档库中有多稀有？越稀有越重要。

```
例: 文档库 1000 篇文档
    "的" 出现在 990 篇 → IDF = log(1000/990) ≈ 0.004  (几乎没价值)
    "CRISPE" 出现在 5 篇 → IDF = log(1000/5) ≈ 5.3  (很有区分度)
```

**为什么用 log**：避免极端值（比如只出现 1 次的词 IDF 会爆炸）

---

### 3. TF-IDF（综合得分）

$$\text{TF-IDF} = \text{TF} \times \text{IDF}$$

**核心思想**：

| 情况 | TF 高 | IDF 高 | TF-IDF | 含义 |
|------|-------|--------|--------|------|
| "的" | ✅ 每篇都多 | ❌ 太常见 | 低 | 停用词，无价值 |
| "CRISPE" | ✅ 出现多次 | ✅ 很稀有 | **高** | **关键词！** |
| "框架" | 中等 | 中等 | 中等 | 有一定价值 |

---

## 一个完整例子

```
文档库（3 篇）:
  D1: "CRISPE 框架 是 提示词 框架"
  D2: "BROKE 框架 用于 推理"
  D3: "的 是 了 框架"

查询: "CRISPE 框架"
```

| 词 | D1-TF | D1-IDF | D1-TF-IDF | D2-TF-IDF | D3-TF-IDF |
|---|-------|--------|-----------|-----------|-----------|
| CRISPE | 1/4=0.25 | log(3/1)=1.1 | **0.275** | 0 | 0 |
| 框架 | 2/4=0.5 | log(3/3)=0 | 0 | 0 | 0 |
| 的 | 0 | log(3/1)=1.1 | 0 | 0 | 0.275 |

**结果**：D1 得分最高（因为"CRISPE"是稀有且相关的词）

---

## 与 BM25 的关系

TF-IDF 是基础版，**BM25 是它的改进版**：

| | TF-IDF | BM25 |
|---|---|---|
| TF 增长 | 线性增长（词越多分越高） | 有上限（避免"关键词堆砌"刷分） |
| 文档长度 | 不惩罚长文档 | 惩罚长文档（长文档更容易命中词） |
| 公式 | 简单乘积 | 更复杂的非线性公式 |

**实际搜索引擎（Elasticsearch、Solr）都用 BM25**，但核心思想（TF × IDF）是一样的。
