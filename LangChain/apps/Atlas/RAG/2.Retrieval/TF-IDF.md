# TF-IDF：文本检索的基本公式

## 起源：为什么需要 TF-IDF？

最早的文本检索（如图书馆搜索）面临一个核心问题：**如何判断一篇文档与用户查询的相关性？**

最简单的想法是"计数"——查询词在文档中出现多少次。但有两个明显问题：

- **问题 A**：一篇文档反复说"法律法律法律法律"，另一篇只说了一次"法律"，前者不一定更相关（可能是为了凑字数）  
- **问题 B**：几乎所有文档都有"的"、"是"这类词，它们对检索毫无帮助，却不能忽略

TF-IDF 就是为了解决这两个问题而设计的。它由两部分组成：

```
TF  = 词在文档中的重要性  →  解决"频率归一化"
IDF = 词在全库中的稀有度  →  解决"常见词降权"
```

---

## 一、TF（Term Frequency，词频）

### 公式

$$\text{TF}(w, d) = \frac{n_d^w}{n_d}$$

| 符号 | 含义 | 例子 |
|------|------|------|
| $n_d^w$ | 词 $w$ 在文档 $d$ 中出现的次数 | 文档中"行政"出现 2 次 |
| $n_d$ | 文档 $d$ 的总词数 | 文档共 13 个词 |

### 直觉

> **一个词在文档中出现的频率越高，它对这个文档就越重要。**

### 例子

文档 "行政机关强行解除行政协议造成损失,如何索取赔偿?"，共 13 个词：

| 词 | 出现次数 | TF |
|---|:---:|:---:|
| 行政 | 2 | 2/13 = **0.154** |
| 机关 | 1 | 1/13 = **0.077** |
| 强行、解除、协议... | 各 1 | **0.077** |
| ，、？ | 各 1 | **0.077** |

"行政"出现了 2 次，TF 最高（0.154），意味着它对这篇文档最重要。

### TF 解决的问题

解决了"**问题 A**"：长文档因为总词数 $n_d$ 大，每个词的 TF 自然会被压缩。1000 词的文档出现 5 次"法律"（TF=0.005），和 100 词的文档出现 1 次"法律"（TF=0.01），后者 TF 更高——确实更相关。

## 二、IDF（Inverse Document Frequency，逆文档频率）

### 公式

$$\text{IDF}(w) = \log\left(\frac{N}{\text{df}(w)}\right)$$

| 符号 | 含义 | 例子 |
|------|------|------|
| $N$ | 文档库中文档总数 | 6 篇 |
| $\text{df}(w)$ | 包含词 $w$ 的文档数 | "的"出现在 3 篇 |

### 直觉

> **一个词在越少的文档中出现，它对区分文档就越有价值。**

| 词的类型 | df(w) | IDF | 含义 |
|---------|:-----:|:---:|------|
| **停用词**（的、是、了） | 接近 N | ≈ 0 | 毫无区分价值 |
| **常见词**（框架、方法） | 中等 | 中等 | 有一定价值 |
| **稀有词**（CRISPE、两万元） | 很小 | 很高 | 高区分度 |

### 为什么 IDF 要用 $\log$？

这是用户问到的最关键的问题。来看不加 log 的情况：

```
文档库 6 篇:

  不加 log:
    "的"   → df=3 → N/df = 6/3 = 2
    "行政" → df=1 → N/df = 6/1 = 6
    "走私" → df=1 → N/df = 6/1 = 6

  加了 log:
    "的"   → log(6/3)   ≈ 0.693
    "行政" → log(6/1)   ≈ 1.792
    "走私" → log(6/1)   ≈ 1.792
```

**加了 log 的效果**：

| 函数 | df=1 → df=2 → df=3 的变化 | 效果 |
|------|:------------------------:|------|
| 原始值 N/df | 6 → 3 → 2（线性下降） | ❌ 变化太快 |
| **log(N/df)** | **1.79 → 1.10 → 0.69（平滑下降）** | **✅ 合理的压缩** |
| sqrt(N/df) | 2.45 → 1.73 → 1.41 | ❌ 压缩不够 |
| 1/(N/df) = df/N | 0.17 → 0.33 → 0.50（反了） | ❌ 反转了 |

**关键性质**：

- $\log(1) = 0$：如果某个词在所有文档中都出现，IDF=0 → 它对检索完全没贡献
- $\log(\text{大值}) \approx \text{平缓增长}$：稀有词仍然权重高，但不会碾压其他词

### IDF 解决的问题

解决了"**问题 B**"：常见词（的、是）的 IDF ≈ 0，即使 TF 很高，TF-IDF 整体分数也很低。稀有词（CRISPE、两万元）的 IDF 很高，即使只出现一次，也能获得高权重。

## 三、TF-IDF（综合公式）

### 公式

$$\text{TF-IDF}(w, d) = \text{TF}(w, d) \times \text{IDF}(w)$$

### 完整例子

文档库 6 篇法律文档，查询 **"行政 赔偿"**：

```
查询分词: ["行政", "赔偿"]

文档 0: "行政机关强行解除行政协议造成损失,如何索取赔偿?"
  行政: TF=0.154 × IDF=1.099 = 0.169
  赔偿: TF=0.077 × IDF=1.099 = 0.085
  Score = 0.169 + 0.085 = 0.254 ← 唯一真正相关的文档

文档 2: "我在微信上被骗了,请问被骗多少钱才可以立案?"
  行政: TF=0
  赔偿: TF=0
  Score = 0 ← 完全不相关，零匹配
```

### 四种情况的直觉

| | TF 高（频繁出现） | TF 低（偶尔出现） |
|---|---|---|
| **IDF 高（稀有词）** | ⭐ **最高权重** — 比如"CRISPE"在仅讲 CRISPE 的文档中出现了多次 | ✅ **中等权重** — 比如"两万元"只出现一次，但很稀有 |
| **IDF 低（常见词）** | ❌ **低权重** — 比如"的"在该文档中出现很多次，但每篇都有 | ❌ **忽略不计** — 没有价值 |

## 四、从 TF-IDF 到 BM25

TF-IDF 是基础版本，**BM25** 是它的改进版，被 Elasticsearch、Solr 等搜索引擎使用。

### 公式对比

| | 原始 TF-IDF | BM25 |
|---|---|---|
| **TF** | $\text{TF} = \dfrac{n_d^w}{n_d}$ | $\text{TF\_BM25} = \dfrac{(k_1+1) \cdot \text{TF}}{k_1 \cdot \left(1-b + b \cdot \dfrac{|d|}{avgdl}\right) + \text{TF}}$ |
| **IDF** | $\log\dfrac{N}{\text{df}(w)}$ | $\log\dfrac{N - \text{df}(w) + 0.5}{\text{df}(w) + 0.5}$ |

### BM25 的改进

| 问题 | TF-IDF | BM25 |
|------|--------|------|
| **TF 无限增长** | 一个词出现 100 次，TF=1.0（线性） | **有上限**，$k_1$ 参数控制饱和速度 |
| **长文档偏差** | 长文档更容易包含更多词，不惩罚 | **惩罚长文档**，$b$ 参数控制长度惩罚 |
| **IDF 极端值** | log(N/df) 在 df=0 时爆炸 | **加平滑项**，避免除零 |

### 参数说明

- **$k_1$**（通常 1.2~2.0）：控制 TF 的饱和速度。$k_1$ 越大，TF 增长越快（越像原始 TF）
- **$b$**（通常 0.75）：控制文档长度惩罚。$b=0$ 不惩罚长度，$b=1$ 完全惩罚
- **$|d|$ / avgdl**：当前文档长度 / 平均文档长度。长文档 $|d|$ 大，TF 被压缩

## 五、代码对应关系

对照 `SparseRetrieval.ts` 的实现：

```typescript
// TF = 词在文档中的出现次数 / 文档总词数
for (const [term, count] of termCount) {
  tf.set(term, count / totalTerms);
}

// IDF = log(文档总数 / 包含该词的文档数)
idf(term: string): number {
  return Math.log(docCount / (df + 1));
}

// TF-IDF = TF × IDF
tfidf(docIndex: number, term: string): number {
  return tf * this.idf(term);
}

// 查询评分 = 查询中所有词的 TF-IDF 之和
search(query: string) {
  for (const term of queryTerms) {
    score += this.tfidf(i, term);
  }
}
```

运行结果验证：

```
检索: 行政 赔偿
  doc[0] 得分: 0.2535  行政机关强行解除行政协议造成损失,如何索取赔偿?...

检索: 起诉
  doc[1] 得分: 0.0924  借钱给朋友到期不还得什么时候可以起诉?怎么起诉?...
  doc[3] 得分: 0.0330  公民...能不能去法院起诉吗?...
```

结果符合预期：
- "行政 赔偿"只匹配文档 0（唯一提到这两个词的法律文档）
- "起诉"匹配文档 1 和 3（都含有"起诉"一词），文档 1 出现 2 次所以分更高

## 六、TF-IDF 在 RAG 中的角色

```
混合检索 = 稀疏检索(TF-IDF/BM25) + 稠密检索(embedding)

  稀疏检索（TF-IDF/BM25）        稠密检索（语意向量）
  ┌──────────────────┐          ┌──────────────────┐
  │  精确关键词匹配     │          │  语意相似度计算     │
  │  "CRISPE"→匹配CRISPE│          │  "提示词框架"→匹配  │
  │  "起诉"→匹配起诉    │          │  所有框架    │
  │  可解释，无需训练    │          │  理解同义词     │
  │  对专有名词友好      │          │  理解上下文     │
  └──────────────────┘          └──────────────────┘
          ↓                              ↓
          └───────── RRF 融合排序 ─────────┘
                          ↓
                    final top-k
```

### TF-IDF 弥补稠密检索的不足

| 场景 | 稠密检索表现 | 稀疏检索（TF-IDF/BM25）表现 |
|------|:--------:|:--------:|
| 搜"CRISPE" | ❌ 可能被 BROKE 冲淡（语义相近） | ✅ 精确命中 |
| 搜"第 3 章第 5 条" | ❌ embedding 不理解精确位置 | ✅ 按关键词精确匹配 |
| 搜"两万元" | ❌ 可能与"金额"混淆 | ✅ 精确命中数字 |
| 搜"如何索取赔偿" | ✅ 能匹配"赔偿" | ✅ 也能匹配"赔偿" |

**两者结合（Hybrid Search）是工业级 RAG 的标准实践。**
